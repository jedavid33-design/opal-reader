OpalReader v1.2.3 — Audio cache / playback repair

Primary repair
- Playback no longer writes downloaded MP3 Blob objects into IndexedDB.
- R2 remains the durable audio source of truth.
- A fetched R2 segment is returned directly to the persistent audio player.
- This removes the Safari/iOS IndexedDB Blob write from the segment/chapter handoff path.
- Book-audition local cache writes are best-effort only and can no longer abort playback/audition if Safari rejects them.

Why
Safari was intermittently raising:
  Error preparing Blob/File data to be stored in object store
That exception could abort a segment transition, poison generation/playback state, and make an app restart appear to fix the problem.
