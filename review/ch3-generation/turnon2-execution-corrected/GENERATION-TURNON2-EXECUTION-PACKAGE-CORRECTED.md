2. **The disqualifying-gap rule (A5).** Inside the lookback window, any of the following is a **disqualifying observation**, and the 12-hour clock restarts at that observation: (a) any logged run whose `/v2` reads returned the 1101 signature (HTTP 500, body `error code: 1101`) — or any non-200 on the monitor's plan/job/quota/snapshot reads; (b) an **evidence gap**: an interval between consecutive logged runs **longer than 40 minutes** (one missed run at the 20-minute cadence is the largest tolerable slippage); (c) the window's tail: the most recent logged run must sit **≤ 40 minutes before** the census start. Qualification is **elapsed wall-clock time**: the interval from the first evidencing clean run to the census start must be **≥ 12 hours** with every run inside it clean and every consecutive interval ≤ 40 minutes. (The ruling's precision, OQ-7: 36 clean readings at perfect cadence span only 11h40m — a reading count is not the measure; elapsed time is.)

### §4.10 The WAIT law — deterministic deadlines (A1, OQ-1)

**Definitions.** PT-day reset = **07:00Z daily** (midnight PT; the guard's day boundary). For a smoke plan created at **T0**:

- **Inner bound** = **T0 + 4h**.
- **Outer bound** = **(first PT-day reset strictly after T0) + 4h**.
- **Extension deadline** = **outer bound + 4h** — reachable only if the extension is **earned** (below).
- **Absolute cap** = **T0 + 52h**. No classification lands later than the cap, under any branch.

**Disposition of the extension deadline (R2).** The corrective proposal's Option C text carried the extension further than this package does: its extension was "one further window (**second reset + 4 hours**)" (proposal §3-C; OQ-1 as recommended there). Rowan's review of this package (handoff `RT-H-20261107-cc21c8`) **accepts the shorter deadline as a conservative design amendment**, and this corrected filing records that disposition expressly: the extension deadline is **outer bound + 4h**; the **T0 + 52h absolute cap is preserved unchanged**; and every formula and worked example in this package — §3's schedule table and the worked example below included — is stated on, and has been verified consistent with, the outer + 4h basis. No deadline formula changed under this correction; the disposition is what was missing, and it is now of record.

**WAIT entry — evaluated once, at the inner-bound read.** If at the inner bound the plan is **not complete** and its **only** obstruction is a `parked_quota` / `provider_attempt_budget` park with **failed = 0**, no entry failed or blocked, and every other §4.11 COMPLETE-evidence item either satisfied or still satisfiable by the plan's resumption, the plan enters the named state **WAIT** instead of landing FAILED. WAIT entry is recorded in the working log with the inner-bound read's full values: the plan's totals — of which the **done count is the extension predicate's sole baseline** — and, recorded alongside as **diagnostic evidence only**, that read's dispatches and cumulative attempt/execution counts (R1: recorded, never predicate-bearing). If the plan is incomplete at the inner bound for **any other reason**, WAIT does not open and the classification lands at the inner bound (§4.11).

**During WAIT.** The system remains enabled under this section's authority alone (§4.12's no-indefinite-enabled predicate names WAIT as one of its enumerated states). **The extension — earned only by completed-segment progress (R1).** At the **outer-bound read**, compare the plan's completed-segment count against the inner-bound read's recorded baseline: the extension is **earned** iff **done_outer > done_inner** — and by nothing else. An increase in the plan's cumulative attempt or execution count **without** an increase in completed segments is **insufficient and never earns the extension**; attempt and execution movement between the two reads is recorded in the working log as **diagnostic evidence only** — it informs the record's account of the plan's behavior and moves no deadline. Any non-quota stop state, any failed entry, any foreign movement, or any trigger event exits WAIT immediately into the ordinary classification/trigger path, judged on its own terms at that moment.
