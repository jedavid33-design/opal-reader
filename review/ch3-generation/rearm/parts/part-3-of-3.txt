## 7. Containment (pre-authorized inside this gate)

- **Re-halt and re-pause are ALWAYS permitted inside this
  gate without further approval.** Returning to the
  pre-state is the safe direction: on any anomaly at any
  point — a STOP condition, any watched-set movement, any
  ambiguity that read-back cannot resolve — the executor
  **re-pauses the queue first** (cf-api PUT,
  `delivery_paused: true`, read back; it stops new
  deliveries while the flip lands) and **then re-halts**
  (metadata flip back to `"1"`, same mechanism as R1, read
  back), then STOPs and files the record. Neither
  containment write needs a fresh go; both are recorded as
  their own read-back steps in the execution record.
  Containment is available at every step, including before
  R1 (when it is trivially satisfied), during both
  windows, and after R4.
- **Containment is NOT a rollback.** It touches no code
  and no data: the flip is a one-value binding change on
  byte-identical parts of the **same build**
  (`63d7260e…` before, during, and after), and the pause
  is a queue setting. No build changes hands at any point
  in this gate, in either direction.
- **Beyond containment, nothing.** If containment itself
  fails or read-back cannot establish the contained state,
  the gate stops with the system in whatever state
  read-back proves, and the next step is Julie's fresh
  decision — not a retry, not a fix-forward, not a
  rollback.

## 8. STOP law

- **Ambiguity at any step = stop and only look.** A fault
  or lost response is never treated as proof that a
  mutation did or didn't land (Rowan's caution, carried
  from gate (b) through every gate since). Read-back
  establishes the state; uncertainty is a STOP, with
  containment (§7) as the only writes permitted while
  uncertain — and only because their direction is safe
  regardless of which way the ambiguous write landed
  (re-halting an already-halted system and re-pausing an
  already-paused queue are both no-ops if already there;
  each is still read back).
- **One attempt:** if the gate is contained or STOPped, a
  second attempt requires Julie's fresh authorization.
  The execution record states exactly where it stopped and
  the state the system was left in.
- **No step is skipped, merged, or reordered** to recover
  time or work around a failure. In particular the unpause
  stays LAST among mutations under all circumstances: no
  state in which the queue is unpaused while a precondition
  or a window is outstanding is reachable inside this
  gate except transiently after R4, where R5/R6 are the
  standing watch and §7 the standing remedy.
