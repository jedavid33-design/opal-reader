OpalReader v1.2.2 — Storage-state repair

Primary fix:
- Original EPUB File/Blob is no longer stored inside the frequently rewritten book record.
- IndexedDB schema upgraded to v2 with a separate `epubs` store.
- Existing books are migrated automatically on first launch:
  * EPUB binary moves to `epubs`
  * book.epub keeps only its filename/reference
- New EPUB imports are stored separately from book/playback state.
- Cloud sync uploads the EPUB from the separate local store.

Why:
iOS/Safari was intermittently throwing:
"Error preparing Blob/File data to be stored in object store"
during playback/generation state saves, which could interrupt:
- segment/chapter handoff
- generation progress/retry
- subsequent generation until app restart

Preserved:
- Current book/chapter data
- R2 audio cache
- provider setup
- existing generation queue behavior
- Speechify integration
- TTS usage ledger

Versions:
- App/Worker: 1.2.2
- Service worker cache: v25
